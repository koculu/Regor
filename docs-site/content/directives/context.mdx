On a component, `:context` updates its properties from an object, including properties that are not declared in `props`.

On other tags, it uses the object as the context for that element and its children.

`r-context` is the default alias and works the same way.

## Using `:context` on components

```html
<MyComponent :context="{ title: pageTitle, theme: activeTheme }"></MyComponent>
<MyComponent r-context="{ title: pageTitle, theme: activeTheme }"></MyComponent>
```

The component can use `title` and `theme`. When `pageTitle` or `activeTheme` changes, the corresponding component properties update.

## Using `:context` on normal tags

Use `:context="user"` to write `name` instead of `user.name` on that element and inside it. `r-context` works the same way.

```html
<div :context="user">
  <span>{{ name }}</span>
</div>
```

Here, `name` means `user.name`. Elements outside the `div` keep their own context.

The object is chosen once when the element is bound. Its ref properties remain reactive.

## Choosing a binding

Use `:context` to set several component properties at once or to avoid repeating an object name in child bindings.

Use `:prop-name="value"` or `r-bind:prop-name="value"` to bind a single property declared in the component's `props` list.

Use `r-bind="{...}"` or `:="{...}"` to set element attributes.

## Combining `:context` with declared props

```html
<UserCard
  :user-id="selectedUserId"
  :context="{ badge: userBadge, canEdit: isAdmin }"
></UserCard>
```

```ts
const UserCard = defineComponent('<section>...</section>', {
  props: ['userId'],
  context: (head) => ({
    userId: head.props.userId,
    badge: head.props.badge,
    canEdit: head.props.canEdit,
  }),
})
```

In this example:

- `userId` comes from declared prop binding (`:user-id`)
- `badge` and `canEdit` come from `:context`
